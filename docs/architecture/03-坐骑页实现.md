# 03 坐骑页实现

## 1. 页面结构

坐骑页由左侧列表和右侧详情组成：

```text
左侧 310px 左右                右侧剩余区域
┌────────────────┐          ┌────────────────────────┐
│ 可滚动坐骑列表  │          │ 图标、名称、状态、来源  │
│ 图标/名称/来源  │          │ 描述                    │
│ 星标            │          │ 3D 坐骑模型             │
│ 滚动提示/范围   │          │ 重置视角/设置偏好        │
└────────────────┘          └────────────────────────┘
```

实现文件：`UI/Mounts.lua`。

## 2. 可滚动列表

使用 `FauxScrollFrameTemplate`，不要为全部坐骑创建 Frame。

实现步骤：

1. 创建固定数量的可见行。
2. `FauxScrollFrame_Update()` 设置总记录数、可见行数和行高。
3. `FauxScrollFrame_GetOffset()` 取得首条数据索引。
4. 将记录绑定到复用行。
5. 行和 ScrollFrame 都接收鼠标滚轮。
6. 限制 offset 在 `0..总数-可见数`。

列表必须有明确背景/边框和滚动条。底部增加范围提示，例如“滚轮及拖动滚动条查看更多坐骑 13-24 / 24”，解决用户误以为只有当前几条的问题。

## 3. 列表行

复用 `UI.CreateMountListRow()`。每行包含：

- 40px 左右的图标。
- 名称。
- 来源。
- 偏好星标。
- 选中背景。
- 已收集/未收集亮度。

左键选择记录，右键打开 `UIDropDownMenu`。右键菜单至少有“召唤”和“设为偏好/取消偏好”。

## 4. 权限与状态

未收集坐骑必须同时在三层阻止操作：

1. Catalog 不返回有效 favorite。
2. 菜单项禁用。
3. 实际执行函数再次检查 `record.collected`。

不要只把按钮显示为灰色而仍允许 Bridge 请求。

## 5. 详情区

选择记录后刷新：

- 图标及收集边框。
- 名称。
- “已收集/未收集”。
- 来源。
- 描述。
- 偏好按钮文字和可用状态。
- 当前 3D 模型。

无选中项时显示明确空状态，不保留上一条坐骑资料。

## 6. 模型加载

模型控件使用 `PlayerModel`。坐骑模型可能来自本地目录或 Bridge 完成的准备过程，因此模型加载是异步的。

关键状态：

- `scModelGeneration`
- `scModelTasks`
- `scModelReady`
- `scBaseScale`
- `scZoom`
- `scDragging`

每次选择新坐骑：

1. generation 加一。
2. 清除旧任务和拖动状态。
3. `ClearModel()`。
4. 重置 facing、position、基础缩放和 zoom。
5. 请求或设置新模型。
6. 延迟检查模型是否准备完成。
7. 只有 generation 仍一致时才提交结果。

这可以避免快速点击 A→B→A 时，B 的延迟回调覆盖 A。

## 7. 旋转与缩放

- 左键按下记录 cursor X。
- `OnUpdate` 只在拖动期间读取差值并修改 facing。
- 松开鼠标立即清除拖动状态。
- 滚轮改变 `scZoom`，最终缩放必须是 `scBaseScale * zoomFactor`。

禁止使用“当前 Scale × 新倍率”，否则反复选择后模型会越来越大。

“重置视角”应恢复固定 facing、position、base scale 和 zoom，而不是重新创建模型。

## 8. Bridge 调用

- 模型准备：`SC.Bridge.RequestModel(mountId, callback)`。
- 召唤：`SC.Bridge.SummonMount(mountId, callback)`。

回调需要处理：成功、Bridge 不可用、超时、服务端拒绝。失败时给用户文字提示，但不要破坏当前选择。

当前源码的右键菜单只检查 `Bridge.SummonMount` 函数是否存在，而该函数在 `Bridge.lua` 中始终定义；因此离线时按钮目前不会提前禁用，而是在点击后通过回调返回失败。若要做到离线时直接禁用，需要额外检查 `Bridge.connected` 或提供统一 `Bridge:IsActionAvailable()`，并在连接状态变化时刷新页面。

## 9. 刷新逻辑

`page:Refresh()` 应按顺序：

1. Catalog 查询全部符合条件记录。
2. 更新 FauxScrollFrame。
3. 校正 offset。
4. 刷新可见行。
5. 更新收藏数和进度条。
6. 保留仍存在的选择；否则选择第一项或清空。

不要因为搜索框每输入一个字符就重新创建模型控件。

## 10. 验收标准

- 列表边界和滚动条明显。
- 用户一眼能看到还有更多坐骑。
- 未收集坐骑不能召唤或偏好。
- 右键菜单能执行已收集坐骑操作。
- A→B→A 后模型大小一致。
- 拖动旋转和滚轮缩放工作。
- 重置视角可恢复固定构图。
- 模型失败时显示“无法预览”，不出现 Lua 错误。
- 顶部数字和绿色进度同步。

## 11. 最小部署与游戏测试

客户端退出后，将插件同步到测试客户端：

```powershell
$source = (Resolve-Path '.\addon\SoloCollections').Path
$target = 'D:\path\to\WoW\Interface\AddOns\SoloCollections'
New-Item -ItemType Directory -Path $target -Force | Out-Null
Copy-Item -Path (Join-Path $source '*') -Destination $target -Recurse -Force
```

进入游戏后按以下顺序测试：

1. 点击右下角收藏按钮，默认打开坐骑页。
2. 滚轮滚动到列表末尾，确认滚动条范围和末行正确。
3. 依次点击三个坐骑，模型不能继承上一只的缩放。
4. 拖动和滚轮操作右侧模型。
5. 对已收集和未收集坐骑分别打开右键菜单。
6. 断开或禁用服务端 Bridge 后再次召唤，确认错误可读且 pending 会释放。
