# 09 武器与副手显示

> **当前状态（2026-08-14）**：外观物品卡的武器显示已改为 Transmorpher
> 3.0.0 的玩家 `DressUpModel` 路径。固定预览 Creature、`14307`、
> `PREVIEWCREATURE:WEAPON`、ezCollections 武器镜头和 standalone weapon
> actor 均不再驱动物品卡。

## 1. 当前唯一运行路径

```text
SoloCollections Catalog itemId / weaponType / slot
        ↓
EzWardrobe.Model 解析 Main Hand / Off-hand / Ranged
        ↓
Transmorpher Classic race / sex / render-slot / subclass setup
        ↓
玩家 DressUpModel: ClearModel + SetUnit("player")
        ↓
SoloCam v11 PreviewItemBridge: 原生 Undress
        ↓
SetPosition / SetFacing
        ↓
SoloCam v11 PreviewItemBridge: 装备栏语义映射 + 原生 TryOn(itemId, modelSlot)
        ↓
SetSequence
```

页面仍固定复用 18 张卡片。收藏状态、权限、revision、持久化和最终应用动作
仍由 SoloCollections/SC2 负责；武器预览桥只影响当前卡片的本地模型。

## 2. 为什么使用合并 DLL

Transmorpher 的武器预览依赖客户端原生模型方法：

```text
TryOn   0x00597FC0
Undress 0x00597BA0
```

它通过 Hook `PlayerModel:SetCreature` 接收保留数值请求。SoloCam 原有的
direct-display bridge 也拥有同一个 Hook 点，因此完整 Transmorpher DLL 与
SoloCam 不能并列注入。现行方案把预览请求解码合入 SoloCam v11，客户端目录
只允许存在一个 Hook 所有者。

模型对象不能再通过旧的 `ResolveScriptObject` 一参数调用取得，因为该函数
依赖调用者寄存器。v11 按客户端自己的 getter 路径解析：

```text
lua_rawgeti(L, widgetIndex, 0)
→ lua_touserdata(L, -1)
→ lua_settop(L, -2)
```

这样 TryOn 始终作用于发出请求的那张卡片，不会写到另一模型或无效对象。

## 3. 预览协议

Lua 使用小于 `0x20000000` 的保留范围：

```text
0x10000000 + itemId
    自动槽位 TryOn

0x18000000 + equipmentSlot * 0x00100000 + itemId
    equipmentSlot 16 = Lua Main Hand carrier
    equipmentSlot 17 = Lua Off-hand carrier
    equipmentSlot 18 = Lua Ranged carrier

0x1FFFFFFF
    Undress
```

打包格式与 Transmorpher `DressingRoom.lua` 一致；三个值均保持在
`0x1FFFFFFF` 以内。DLL 只接受 16、17、18，其他槽位按无效请求处理。解包后
不能把这三个 Lua 装备栏直接传给底层：build 12340 原生模型槽为主手 15、
副手 16；远程需要由原生 InventoryType 分发器自动选择。

未知值、协议空洞和无效 itemId 必须在 DLL 内消费为 no-op，不能落回原生
Creature cache 查询。

## 4. Transmorpher 构图数据

`Data/TransmorpherPreviewSetup.lua` 是 Transmorpher 3.0.0 Classic 配置的
精确投影：

```text
source commit:
8a8140fa54e424699da00d3a21359b43b79efddc

source PreviewSetupDB.lua SHA-256:
B550F596C7FE94D5B3844D9ECD2D5A0B44BAD2E6E2B2525C3A6A92FCD3D039B4
```

查找键为：

```text
raceFileName → sex → actual render slot → weapon subclass
```

`OH`、`MH`、`1H` 前缀先决定真实渲染槽位，再剥离前缀查基础武器
子类。盾牌和 Held in Off-hand 固定走副手；弓、弩、枪、魔杖和投掷武器固定
走远程。两手武器、长柄和法杖走主手。

钓鱼竿不是 Transmorpher 的原始筛选类别；SoloCollections 将它映射到 Staff
构图，但仍使用同一玩家模型和原生 TryOn 路径。

## 5. 必须保持的渲染顺序

武器卡严格使用 Transmorpher `PreviewList_RenderItem` 的顺序：

1. Reset：位置和朝向归零、清模型、重新 `SetUnit("player")`；
2. Undress；
3. `SetPosition(setup.x, setup.y, setup.z)`；
4. `SetFacing(setup.facing)`；
5. 强制目标槽位 TryOn；
6. `SetSequence(setup.sequence)`。

`OnUpdateModel` 只恢复 sequence。武器卡不再每帧执行
`SetSequenceTime`，也不调用 ezCollections 武器 camera 或 SoloCam M2 camera。

灯光使用 Transmorpher `DressingRoom.lua` 的 `defaultLight`，不是旧的
standalone weapon 显式灯光参数。

## 6. 能力握手与 /reload

SoloCam 只能在全部地址和原字节都匹配 build 12340 时安装 Hook。Hook 安装后，
它在 WoW 主窗口定时器上调用 `FrameScript_Execute` 发布：

```lua
{
    soloCamVersion = 11,
    previewProtocolVersion = 1,
    features = {
        directDisplayV1 = true,
        previewTryOnV1 = true,
    },
}
```

定时发布使 AddOn 首次加载和 `/reload` 后都能恢复能力。AddOn 只在
“未就绪 → 就绪”转换时重绑当前可见武器卡，不能每秒重复 TryOn。

能力缺失或版本不匹配时，武器卡显示物品图标和明确原因；不得退回固定
Creature、NPC、standalone display 或旧镜头。

## 7. 与护甲和套装的边界

- 护甲卡继续使用 ezCollections Classic 种族、性别、部位镜头；
- 武器卡只使用 Transmorpher 构图；
- 套装页继续使用既有套装预览，不经过 PreviewItemBridge；
- 所有生产动作仍使用稳定 `collectionId`；
- 模型显示只使用 `itemId`；
- 未收集武器可以本地预览，但不能绕过 SC2 权限执行应用。
