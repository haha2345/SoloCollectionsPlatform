# 09 武器与副手独立模型

## 1. 最终保留路线

武器和副手不使用角色换装局部镜头，而是只显示物品本身。当前成功路线为：

```text
ItemDisplayInfo / ItemVisual
        ↓
生成独立武器 M2 及纹理引用
        ↓
CreatureModelData + CreatureDisplayInfo
        ↓
聚合 Patch-W.MPQ / locale patch
        ↓
Wardrobe.lua 发送 direct display-info request
        ↓
SoloCam.dll 创建稳定 synthetic creature record
        ↓
PlayerModel 显示独立武器 + 显式灯光
```

完整实现交接和命令已经整理在：

[WEAPON_MODEL_DISPLAY_HANDOFF.md](../../client-extension/SoloCam/WEAPON_MODEL_DISPLAY_HANDOFF.md)

本篇用于说明收藏系统如何接入以及其他模型必须遵守的边界。

## 2. 为什么原生路线失败

### 2.1 `SetCreature(displayId)` 不是 display-info API

3.3.5 Lua 的 `PlayerModel:SetCreature(number)` 会把 number 当成 creature entry 查询。如果直接传 `CreatureDisplayInfo.ID`，可能出现：

- NPC 或怪物模型；
- 白色人物；
- 空模型；
- 无效指针导致 `ERROR #132`。

因此 Lua 使用保留数值空间：

```lua
local DIRECT_DISPLAY_REQUEST_BASE = 0x6F000000
model:SetCreature(DIRECT_DISPLAY_REQUEST_BASE + creatureDisplayId)
```

DLL 拦截该请求并直接绑定 display-info 对应的稳定记录。

### 2.2 通用 `Model` 不能完成这条绑定

武器资源需要 `OBJECT_SKIN` 等纹理绑定。简单的 `Model:SetModel()` 曾出现：

- 完全黑色，仅特效发光；
- 蓝白棋盘盒子；
- 有轮廓无纹理；
- 什么都不显示。

最终保留 `PlayerModel + direct display-info bridge`，并显式调用 `SetLight`。

### 2.3 不要用 NPC 占位

为每件武器创建 NPC/creature entry 会污染数据语义，且此前已经出现卡片显示怪物、NPC 头像的错误。synthetic record 只存在客户端扩展的稳定内存结构中。

## 3. Lua 端接入

`addon/SoloCollections/UI/Wardrobe.lua` 中主手和副手属于 standalone slot：

```text
MAINHAND
OFFHAND
```

卡片刷新时应：

1. 读取记录中的 `creatureDisplayId` 或生成映射后的 display ID；
2. 清理上一件物品状态；
3. 发送 `DIRECT_DISPLAY_REQUEST_BASE + displayId`；
4. 设置独立模型 facing、scale、position；
5. 应用显式灯光；
6. 若模型异步加载，在当前 generation 仍有效时再补一次 framing。

不要把主手/副手交给角色 `TryOn` 分支。

## 4. 资源生成工具

核心脚本位于：

```text
client-extension/SoloCam/scripts/
```

保留工具：

- `build-weapon-models.ps1`：批量组织武器资源生成与打包；
- `build_creature_weapon_assets.py`：生成 creature-display 桥接资产和映射；
- `append_item_camera.py`：为独立物品 M2 添加安全的物品 camera；
- `patch_item_m2_textures.py`：修正 M2 纹理引用；
- `build-weapon-ab-diagnostics.ps1`：构建 A/B 诊断包，定位黑模和纹理问题。

资源源目录要区分：

- `Item\ObjectComponents\Weapon`；
- `Item\ObjectComponents\Shield`。

盾牌不能按普通武器路径盲目处理。

## 5. MPQ 组织方式

不需要、也不应该为每一件武器创建一个 MPQ。

正确组织是：

- 一个聚合的 `Patch-W.MPQ` 保存所有生成的 M2、皮肤和通用资源；
- 一个 locale patch，例如 `patch-zhCN-6.MPQ`，保存需要覆盖的 locale DBC/映射；
- 映射生成器批量为所有武器分配 `CreatureModelData`、`CreatureDisplayInfo` 和 direct display ID。

新增一批武器时，重建同一组聚合 patch。模型、贴图和 DBC 行只生成一次；多个收藏记录引用同一资源，不复制整个 MPQ。

注意：当前 `build-weapon-models.ps1` 不是对客户端同名 MPQ 做增量合并。它根据脚本中的 `$Models` 从头创建两个新包，使用 `-Deploy` 时会先备份、再以 `Copy-Item -Force` 替换目标 `Patch-W.MPQ` 和 locale patch。因此 `$Models` 必须包含希望保留在这两个生成包中的全部条目；如果目标同名 MPQ 还承载其他自定义资源，不得直接部署，应先改成合并流程或换用独立 patch 名称。

建议生成稳定 manifest：

```text
itemId -> sourceM2 -> generatedM2 -> creatureModelDataId
       -> creatureDisplayInfoId -> texture set -> category
```

只要源文件和分配策略不变，重复构建应产生相同 ID，避免存档或缓存引用漂移。

当前“从任意 item ID 自动反查并分配全部资源”的工具还没有完成。新增物品前需人工完成：

1. 从 `ItemDisplayInfo.dbc` 或物品模板确认 display 信息；
2. 在 MPQ 中定位对应 `Item\ObjectComponents\Weapon` 或 `Shield` 的 M2、SKIN、BLP；
3. 检查 M2 texture lookup 和物品 visual/effect；
4. 为 `CreatureModelData`、`CreatureDisplayInfo` 分配未冲突 ID；
5. 把完整条目加入 `$Models` manifest 后重建。

在自动反查和 ID 分配器完成前，不应把“现有演示武器可重建”描述为“全量武器已自动支持”。

## 6. 正式服风格构图

目标：

- 卡片中只显示武器或副手；
- 黑色背景；
- 模型对角排列并尽量填满安全区域；
- 长武器完整显示，不能截断刃尖或握柄；
- 盾牌正面朝向相机；
- 发光特效可见，但主体不能因灯光不足变黑；
- 名称、收藏状态和 hover 仍由卡片 UI 层绘制。

每类模型可使用默认 framing，再允许记录覆盖：

```lua
record.modelFacing
record.modelScale
record.modelPosition = { x, y, z }
```

不要为每个 item 在 Lua 中硬编码一组分支。应把异常大剑、长柄、盾牌等覆盖值放到数据或生成 manifest 中。

## 7. 黑模和错误模型排查顺序

### 完全黑色但有附魔特效

依次检查：

1. M2 纹理类型是否需要 `OBJECT_SKIN`；
2. 生成皮肤是否进入 patch；
3. `CreatureDisplayInfo` texture fields 是否正确；
4. 是否走了 direct display-info bridge；
5. `PlayerModel:SetLight` 是否应用。

### 蓝白棋盘盒子

这是资源或纹理解析失败，不是 camera 问题。检查路径大小写、MPQ 内部路径、`.blp` 存在性和 M2 texture lookup。

### 显示 NPC/怪物

说明请求落回了原生 `SetCreature(entry)`，或 direct base/Hook 未生效。检查 DLL 是否加载、request base 是否一致以及 synthetic record 构造路径。

### 完全为空

检查 display ID 映射、模型路径、Hook 保护性回退日志以及当前卡片 generation；不要通过不断增大 scale 猜测。

### 打开收藏即崩溃

优先检查传给客户端的 record 生命周期和版本地址。不要把临时栈对象、释放后的字符串或错误结构布局交给客户端。

## 8. 验收清单

- [ ] 主手页能显示至少剑、匕首、法杖或长柄中的三类。
- [ ] 副手页能显示盾牌和至少一种副手物品。
- [ ] 模型有材质，不是黑影或棋盘盒。
- [ ] 卡片间不会串模型，不显示 NPC。
- [ ] 翻页和切换主手/副手不会崩溃。
- [ ] 移动收藏窗口不改变模型比例。
- [ ] 所有武器共用聚合 patch，不为单件武器创建 MPQ。
- [ ] 缺少映射的物品显示明确 fallback，而不是访问无效内存。

## 9. 交给其他模型时的任务模板

```text
实现或调整 SoloCollections 的主手/副手独立模型。
先阅读 client-extension/SoloCam/WEAPON_MODEL_DISPLAY_HANDOFF.md。
必须沿用 PlayerModel + direct display-info bridge + synthetic record + explicit SetLight。
不要把 display ID 直接传给原生 SetCreature，不要用 NPC 占位，不要为每件武器创建独立 MPQ。
资源应批量生成到一个聚合 Patch-W.MPQ 和一个 locale patch。
使用本机 Visual Studio Build Tools 构建，产物留在仓库忽略的构建目录。
```
