# 05 玩具箱实现

## 1. 目标

玩具箱采用正式服的密集图标网格，而不是坐骑页的左右分栏。核心目标是：已解锁玩具可以直接使用、通过右键菜单使用，并能拖到动作栏；物品出售后仍由服务端收藏记录授权使用。

实现文件：`UI/Toys.lua`。

## 2. 网格布局

当前页面每页 18 个卡片，按三列、六行排列。页面只创建18个固定 tile，翻页时替换记录。

每张卡片包含：

- 玩具图标。
- 名称。
- 偏好星标。
- 选中状态。
- 已解锁/未解锁亮度。

底部提供上一页、页码、下一页，以及简短交互提示。

## 3. 收藏状态表现

- 已解锁：图标正常亮度，名称为金黄色。
- 未解锁：图标降低亮度，名称为灰色。
- 偏好：图标左上角金色星标。
- 选中：轻量金色边框。

不要使用覆盖整张卡片的大面积灰色遮罩。

## 4. 使用操作

### 左键

左键点击已解锁玩具直接调用：

```lua
SC.Bridge.UseToy(record.id, callback)
```

未解锁或 Bridge 不可用时立即返回并提示原因。

### 右键菜单

右键使用 `UIDropDownMenu`，菜单包含：

- 使用玩具。
- 设为偏好/取消偏好。

未解锁时“使用”禁用。偏好是否允许未解锁可按产品规则决定；若希望与坐骑一致，应在 Catalog 和执行函数两层限制。

## 5. 拖到动作栏

3.3.5 没有正式服玩具动作类型，因此使用宏作为动作栏载体：

1. 为玩具生成稳定且尽量短的宏名。
2. 宏正文调用 SoloCollections 玩具使用入口。
3. 优先复用已有同名/同正文宏。
4. 不存在时使用 `CreateMacro()` 创建。
5. 使用 `PickupMacro(macroIndex)` 将宏放到鼠标。
6. 玩家把宏放入动作栏。

代码执行前必须检查 `CreateMacro`、`EditMacro` 和 `PickupMacro` 是否存在。还需要处理通用宏和角色宏已满的情况。

动作栏宏最终仍应调用 Bridge，由服务端重新校验收藏状态，不能让宏直接绕过权限。

## 6. 搜索、过滤和分页

`Catalog.Query("TOYS", query, filters, page, 18)` 返回当前页记录、校正页码和总页数。

过滤器至少包括：

- 已解锁。
- 未解锁。
- 偏好。

修改过滤条件后将页码重置为1。当前页超过新总页数时使用 Catalog 返回的校正页码。

## 7. 物品缓存

3.3.5 的 `GetItemInfo()` 可能在第一次查询时返回 nil。页面注册 `GET_ITEM_INFO_RECEIVED`，收到缓存结果后刷新图标、名称和 tooltip。

不要把第一次 nil 结果永久写回 Data。

## 8. 3.3.5 Lua 兼容

早期版本在网格定位时调用 `math.mod`，3.3.5 环境中该字段可能不存在并导致页面创建失败。应使用 `%` 或本地兼容函数：

```lua
local column = (index - 1) % 3
local row = math.floor((index - 1) / 3)
```

后续新增代码同样不能假设正式服 Lua 标准库完整存在。

## 9. 服务端语义

“拾取后解锁、卖掉后仍可使用”需要服务端完成：

1. 拾取或获得物品时识别对应 toy ID。
2. 写入账号/角色收藏表。
3. 客户端同步为 `collected=true`。
4. 使用请求到达时查询收藏表。
5. 服务端施放对应 spell、触发 item effect 或自定义脚本。
6. 检查冷却、战斗、区域和目标条件。

客户端不能通过检测背包替代收藏表。

## 10. 验收标准

- 每页18个卡片，翻页正确。
- 已解锁和未解锁名称颜色清晰可辨。
- 左键和右键都能使用已解锁玩具。
- 未解锁玩具不能使用。
- 拖拽会拾取正确的宏，而不是空光标。
- 宏栏已满时有明确提示。
- 物品信息延迟加载后页面自动补全。
- 玩具出售后仍可由服务端收藏记录授权使用。
