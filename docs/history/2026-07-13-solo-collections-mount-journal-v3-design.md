# SoloCollections 坐骑日志 V3 设计

**日期：** 2026-07-13  
**状态：** 已确认  
**范围：** 坐骑页、公共顶部框架、底部主标签、右下角启动按钮、坐骑模型与召唤桥接

## 目标

将现有自制收藏面板重构为与正式服 `CollectionsJournal` / `MountJournal` 一致的 3.3.5 兼容界面。外观、层级和交互以本地正式服 UI 源码及用户提供的正式服截图为基准；实现层继续使用 3.3.5 可用的 `FauxScrollFrameTemplate`、`PlayerModel`、`UIDropDownMenuTemplate` 和 AddOn Message。

## 已确认方案

采用“方案 B：兼容式正式服回移”。不直接复制正式服依赖的 Atlas、Mixin、ScrollBox、ModelScene API，而是：

- 复刻正式服布局比例、边框、背景、标签和状态；
- 将必要正式服资源导出为 3.3.5 可读取的独立 TGA；
- 用 3.3.5 原生控件重建等价行为；
- 用 mod-ale Lua 对模型缓存和召唤请求做服务端验证与中转。

## 参考差异

正式服结构：

- 主框架为 `PortraitFrameTemplate` 风格的深色金属外壳，参考逻辑尺寸 `703×606`；
- 圆形坐骑头像突出于左上角，数量胶囊位于头像右侧；
- 搜索框位于左侧列表顶部，列表为连续滚动；
- 右侧是独立坐骑展示区，顶部覆盖坐骑图标、名称、来源与描述；
- 标签独立悬挂在主框架下方，选中标签为金色渐变；
- 坐骑模型占据详情区主体并支持旋转。

当前插件问题：

- 大面积棕金自制外壳与正式服框架层级不同；
- 进度条、搜索框和边框使用整张贴图拉伸，产生明显变形；
- 坐骑列表使用固定八行加分页，不能连续滚动；
- `SetCreature` 在本地客户端未完成 creature cache 时会静默显示空白；
- 底部标签仍属于主框内部，没有正式服悬挂效果；
- 启动按钮使用自制箱子图标，而不是正式服 Collections 微菜单图标。

## 布局

### 主框架

- 设计尺寸为 `920×793`，保持正式服 `703:606` 的宽高比例；
- 使用深色金属标题栏和窄边框，去掉大面积金色描边与厚重棕色底板；
- 标题居中显示当前页面名；
- 关闭按钮位于右上角；
- 保留拖动、位置保存、屏幕约束和分辨率响应缩放。

### 顶部区域

- 左上圆形头像使用正式服 `MountJournalPortrait` 资源及金色圆框；
- 头像右侧放置 `所有坐骑  已收藏数` 数量胶囊；
- 顶部中间增加 `已收藏 / 总数` 进度条；
- 进度条采用三段式边框和独立填充纹理，固定高度约 22px，禁止拉伸整张边框；
- 搜索框采用左右端帽加可平铺中段，保留放大镜、占位文字和清除按钮；
- 过滤器按钮紧邻搜索框。

### 坐骑列表

- 左侧内容宽度约 340px；
- 使用 `FauxScrollFrameTemplate`，显示八个复用行并按滚轮/滚动条连续移动；
- 每行包含 38px 坐骑图标、名称、来源、收藏状态和偏好星标；
- 选中行使用正式服式金色高亮，未收集行降低饱和度和透明度；
- 左键选择；右键行或图标打开召唤菜单；
- 移除坐骑页的页码及上一页/下一页按钮。

### 坐骑详情与模型

- 右侧使用 `MountJournal-BG` 风格背景；
- 顶部信息层包含可点击的 38px 坐骑图标、坐骑名、来源、描述和收藏状态；
- 图标左键等价于召唤，右键打开同一上下文菜单；
- 模型位于信息层后方，占据详情区主体；
- 左键拖动旋转，滚轮缩放，按钮恢复默认视角；
- 模型加载流程为：客户端请求 `MODEL` → 服务端白名单验证并调用 `PrimeCreatureQuery` → 返回 `MODEL_READY` → 下一帧 `ClearModel/SetCreature` → 0.1/0.25/0.5 秒有限重试；
- 请求携带递增 `requestId`，迟到响应不得覆盖当前选中坐骑；
- `GetModel()` 为空才显示“无法预览”，元数据始终保留。

## 底部标签

- 保留四项：坐骑、小宠物、玩具箱、外观；
- 标签锚定在主框架 `BOTTOMLEFT` 之外，彼此独立并轻微重叠边缘；
- 未选中为深色金属；选中为金色纵向渐变并与主框架底边产生金色连接光；
- 本轮只统一公共标签外观，不重构小宠物、玩具箱和外观页内容。

## 启动按钮

- 右下角按钮使用正式服 `UI-HUD-MicroMenu-Collections` 图形导出的独立 TGA；
- 保留拖动、保存位置、工具提示和点击开关窗口；
- 不依赖 3.3.5 不支持的 `SetAtlas`。

## 客户端/服务端协议

协议前缀继续使用 `SC1`，保留 `HELLO|1` 握手，并新增：

```text
MODEL|requestId|mountId
MODEL_READY|requestId|mountId
SUMMON|requestId|mountId
SUMMON_RESULT|requestId|ACCEPTED|mountId
SUMMON_RESULT|requestId|ERROR|reason
```

服务端要求：

- 客户端只提交收藏记录 `mountId`，服务端自行映射 creatureId 和 spellId；
- creatureId 和 spellId 必须来自服务器脚本中的固定允许列表；
- `MODEL` 仅执行 `PrimeCreatureQuery`，不改变角色状态；
- `SUMMON` 只允许已收集且目录允许的坐骑；第一阶段目录仍使用固定 demo 收藏状态；
- 禁止客户端传入任意法术并直接施放；
- 骑乘状态、死亡、战斗、载具、飞行等可预先判断的失败由服务端返回明确错误；
- `CastSpell(..., false)` 只表示请求已接受，底层仍执行正常地图和施法规则，因此响应不得宣称施法一定成功；
- 将来迁移 C++ 时保持同一消息语义，客户端 UI 无需重写。

## 兼容性与降级

- 服务端桥接不可用时，列表和详情仍可浏览；
- 模型请求超时后尝试本地 `SetCreature`，失败才显示无法预览；
- 召唤菜单在桥接不可用时禁用并给出提示；
- 所有新 Lua 避免 `math.mod`、Atlas、Mixin、ScrollBox 和现代 `C_*` 收藏 API；
- 新媒体均验证尺寸、扩展名和客户端加载路径。

## 验收标准

- 启动按钮、圆形坐骑头像、主框比例、搜索/进度条、滚动列表、详情层和底部标签与正式服参考保持同一视觉结构；
- 坐骑列表连续滚动，无分页；
- 右键能打开包含召唤/偏好的菜单；
- 模型能够显示、拖动旋转、滚轮缩放和重置；
- 快速切换坐骑时不会被旧模型响应覆盖；
- 所有自动化测试通过，源目录与两个客户端部署目录哈希一致；
- 服务端 Lua 通过语法检查并部署到运行目录；
- 游戏内最终视觉与模型效果需要用户 `/reload` 后截图验收。

## 本轮不做

- 战斗宠物系统；
- 正式服账号级收藏持久化；
- 真实拾取解锁、玩具动作条拖放和外观应用；
- 传家宝、营区标签；
- C++ 服务端模块迁移。
